# 内容验收门禁（内容门）

> 由 wx-newspic-sop 步骤 1 之后、设计决策之前触发加载。如果 PPT 内容不能回答读者最关心的问题，产出就是废图。

---

## 第一部分：分类判定（步骤 0 的一部分）

### 判定时机

写短文之前、确定样式偏好时，同步判定短文类型。

### 判定依据

**核心维度：读者读完之后，期望的交付物是什么？**

| 类型 | 读者的交付物预期 | 判定关键词 |
|------|----------------|-----------|
| 工具介绍 | 一个**可以用的工具** | "XX 是什么""怎么装""怎么用""推荐一个" |
| 教程/指南 | 一项**能照着做完的技能** | "如何""教程""指南""几步搞定""步骤" |
| 观点/评论 | 一个**新的思考角度** | "我怎么看""为什么""是不是""值不值得" |
| 体验/评测 | 一个**是否值得尝试的判断** | "试了一下""评测""体验""到底怎么样" |
| 感悟/随笔 | 一份**情绪共鸣或启发** | "感悟""随笔""这件事让我""突然想到" |
| 福利/推广 | 一个**可领取的实物/资源** | "免费""白嫖""领取""福利""推广" |

### 模糊地带处理规则

**工具介绍 vs 教程/指南**：看内容重心是"介绍这个工具"还是"教你怎么达成某个目标"。前者归工具介绍，后者归教程/指南。

**体验/评测 vs 工具介绍**：看内容重心是"帮你了解这个工具"还是"分享我的使用感受和结论"。前者归工具介绍，后者归体验/评测。

**观点/评论 vs 感悟/随笔**：看有没有明确的论点+论据结构。有明确的论证过程归观点/评论，更多是个人感受和故事归感悟/随笔。

### 判定结果记录

写入短文 frontmatter：
```yaml
category: 工具介绍  # 工具介绍 | 教程指南 | 观点评论 | 体验评测 | 感悟随笔 | 福利推广
```

## 第二部分：验收问题清单

### 一、工具介绍（7 题）

| # | 读者问题 | 本质 |
|---|---------|------|
| Q1 | 这东西是干嘛的？一句话说清楚 | 定位 |
| Q2 | 我为什么要用它？它能帮我解决什么具体问题？ | 价值 |
| Q3 | 用之前我需要准备什么？装什么、有什么门槛？ | 准入 |

## 第二点五部分：文章结构验收

> 独立于类型验收问题清单，检查短文骨架是否包含五个关键结构要素。每个要素 PASS/FAIL。

### 结构要素清单

| # | 检查项 | 通过条件 | PASS/FAIL |
|---|--------|---------|-----------|
| S1 | **开头切入** | 前两段是否用具体场景/痛点带入（"最怕什么""最烦什么"型），非"XX 是 YY"直接定义 | ✅/⚠️/❌ |
| S2 | **用法过渡** | 介绍产品后的下一段是否自然过渡到"怎么用"（"用法很简单"/"举个例子"），而不是继续介绍概念 | ✅/⚠️/❌ |
| S3 | **场景案例** | 是否包含至少一个完整的具体使用场景或社区案例（"有人在用""举个例子"），而非仅抽象描述 | ✅/⚠️/❌ |
| S4 | **结尾收束** | 结尾是否有具象比喻收束（"XX 把 XX 变成了 XX"），而非抽象概念升华 | ✅/⚠️/❌ |
| S5 | **收获明确** | 读者读完能否立刻回答"我可以拿它做什么" | ✅/⚠️/❌ |
| S6 | **封面完整** | Cover Slide 是否包含标题 + 一段简短描述 + 2-3 个内容标签 | ✅/⚠️/❌ |

### 判定规则

- 6/6 ✅ → ✅ 通过，进入第三部分内容门
- ≥ 3 ✅ + 其余 ⚠️ 或 ❌ → ✅ 有条件通过，⚠️/❌ 项在内容门时标记关注
- ≤ 2 ✅ → ❌ 不通过，回退步骤 1 重构文章骨架

### 不通过时的回退策略

- 明确告知队长：哪几个结构要素未达标、建议如何调整
- 只涉及文字结构调整，不涉及页面设计

## 第三部分：第一道门禁 — 内容门（步骤 1 之后，设计决策之前）

### 执行时机

wx-newspic-sop 步骤 1（内容提炼）完成后、步骤 1.5（设计决策）之前。

### 执行流程

**Step A：产出「版面与元素 + 内容对照表格」**

根据分类判定结果，加载对应类型的验收问题清单，然后为每一张 slide 填写以下表格。**生产表格前，先确认 §文章结构验收已通过或已达"有条件通过"。**

```
### 版面与内容对照表（短文类型：XX）

| Slide | 标题/主题 | 包含元素 | 回答的验收问题 | 覆盖评估 |
|-------|----------|---------|--------------|---------|
| 1 | 封面 | 标题、描述文字、内容标签（2-3个） | — | — |
| 2 | XXX | 核心数据/对比/流程 | Q2（价值） | ✅/⚠️/❌ |
| 3 | XXX | ... | Q3（准入） | ✅/⚠️/❌ |
| ... | ... | ... | ... | ... |
| N | CTA | 行动引导 | — | — |
```

**表格填写规则**：
- 封面**三要素验收**：标题 ✅ + 描述文字 ✅ + 内容标签（2-3个）✅，缺一不可
- CTA 不纳入验收（不承担信息传达任务）
- 「回答的验收问题」列：填写该 slide 主要回答了哪个 Q 编号
- 「覆盖评估」列：✅ = 能清晰回答，⚠️ = 模糊/一笔带过，❌ = 完全没答
- 一张 slide 可以回答多个问题，一个问题也可以由多张 slide 共同回答

**Step B：对照验收**

生成表格后，逐条检查：

1. **覆盖率检查**：该类型的所有验收问题，是否都有至少一个 ✅ 对应？
2. **空白检查**：是否有验收问题全部是 ❌（完全没覆盖）？
3. **深度检查**：标注 ⚠️ 的问题，说明"为什么浅"——是文字层面就没想清楚，还是预计图片放不下？

**Step C：判定**

| 判定结果 | 条件 | 处理 |
|---------|------|------|
| ✅ 通过 | 所有必答题至少 ⚠️，无 ❌ | 进入步骤 1.5（设计决策） |
| ⚠️ 有条件通过 | 有 ⚠️ 但无 ❌，且 ⚠️ 数量 ≤ 2 | 允许进入步骤 1.5，但在视觉门时重点检查这些项 |
| ❌ 不通过 | 存在 ❌（完全没覆盖的验收问题） | **回退到步骤 1**：重新提炼内容，补上缺失问题的覆盖，重新生成表格 |

**不通过时的回退策略**：
- 明确告知队长：哪些问题没覆盖、建议在哪几张 slide 补上
- 不要自动补内容，等队长确认方向后再调整
- 回退只涉及文字层面的调整，不涉及 HTML 和渲染

## 硬规则

| 规则 | 说明 |
|------|------|
| 门禁不可跳过 | 内容门是必经环节，不能因为"赶时间"或"内容简单"而跳过 |
| 分类先行 | 没有分类判定结果，不能进入内容提炼 |
| 结构先行 | 文章结构验收不通过，不能进入 Step A 表格生产 |
| 表格必须先产 | 内容门的核心产出是「版面与内容对照表格」，必须先产出表格再验收 |
| 不通过必回退 | 存在 ❌ 时必须回退修改，不能用 ⚠️ 或跳过替代 |
| 回退范围最小化 | 结构验收回退只改文字结构，内容门回退只改文字，不涉及 HTML + 渲染 |
