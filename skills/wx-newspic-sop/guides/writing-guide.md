# 写作规范

> 由 SKILL.md §一（短文编辑规则）触发加载。正文内容规范、AI 味检测清单、正文清理映射、话题标签规则。

---

## 正文内容规范

- 正文只能是**纯文字 + emoji 辅助**，不能有代码块、表格、引用块、加粗、链接
- MD 结构只有两个标题：`## 正文` + `## 相关图片`
- 正文内不要用结构化标题（如 `## Agent 的调度台`），用段落自然过渡
- 产品首次提及需一句话说明「XX 做的是 YY」，不能假设读者认识
- 正文需经 humanizer-zh 去 AI 味处理
- 体量：800-1200 字
- 末尾固定格式（关注引导）：
  ```
  ▒▒▒▒▒▒▒▒▒▒
  关注我，获取更多AI观察与个人思考 🧰☕
  ▒▒▒▒▒▒▒▒▒▒
  ```

## AI 味说话结构禁用清单 ⚠️ 红线

> 以下结构是 AI 生成内容的典型指纹，短文正文中**禁止出现**。

| 禁用模式 | 示例 | 为什么像 AI |
|---------|------|------------|
| 预判读者情绪 | "看完结论挺扎心的" | AI 喜欢替读者定调情绪反应 |
| emoji 开场 + 一句话解释产品 | "💡 Anthropic，做 Claude 的公司" | 模板化引导，像 prompt 产物 |
| "听起来…实际上…"反差公式 | "听起来没那么性感，但实际上…" | AI 最爱用的认知反差句式 |
| 主动贴总结标签 | "一句话总结：" / "核心数据长这样：" | AI 喜欢给自己的论述打标签 |
| 口语化引导词做段落路由 | "再看看经验年限" / "核心数据长这样" | AI 用"来看/接下来"做段间过渡 |
| 自我盖章式评价 | "这个反差很诚实" / "也有意思" | AI 喜欢给自己的内容下价值判断 |
| 建议式收尾 | "想进这种公司，简历别写成…" | AI 结尾习惯性给 actionable takeaways |
| 泛化升华句 | "更大的信号也很清楚" / "这不难理解" | AI 喜欢在论据后加一句"洞察"拔高 |
| "不是 X，是 Y"翻转句连用 | 连续多段用这个句式开头 | AI 论述结构高度模式化 |
| 反问/设问收束 | "比泛泛写一句…更有用？" | AI 用反问强调观点 |

## 小绿书发布时的正文清理 ⚠️ 重要

小绿书（图片消息）只支持**纯文本**，推送前必须清理 Markdown 格式：

| 需清理 | 原文 | 清理后 |
|--------|------|--------|
| 二级标题 | `## Agent 的调度台` | `Agent 的调度台` |
| 加粗 | `**对话即版本控制**` | `对话即版本控制` |
| 行内代码 | `` `/init` `` | `/init` |
| 无序列表 | `- xxx` | `1. xxx`（或直接段落） |
| 斜体 | `*关注我...*` | `关注我...` |
| 分隔线 | `▒▒▒▒▒▒▒▒▒▒` | 保留，可正常使用 |
| 段落分隔 | `段落1。\n段落2。` | `段落1。\n\n段落2。` |

> ⚠️ 微信小绿书渲染规则：`\n\n`（双换行）→ `<br><br>` → **有段落间距**；`\n`（单换行）→ `<br>` → 仅换行，**无段落间距**。发布前务必确认 `--content` 中段落间保留空行（双换行）。

**正文长度限制**（微信 API 实测）：**≤ 1280 字符**。超限报 `invalid content`（errcode: 45166）。单个中文字=1个字符。

> ⚠️ 微信官方文档说 2 万字限制，实测小绿书（newspic）正文限制约 1287 字符。超限即报错。

**允许的内容**：普通文本、emoji、`@` 符号、`#标签`、分隔线符号均可正常使用。唯一的限制是正文总长度不超过约 1280 字符。

## 话题标签（红线规则）

- **必须**：将 frontmatter `tags` 字段中的**每一个**标签，全部转换为文末 `#标签` 格式，缺一不可
- 标签尽量大众化（搜索量高），兼顾精准词
- 示例：frontmatter `tags: [AI, 教条主义, 产品思维, AI设计, 效率工具]` → 正文末尾 `#AI #教条主义 #产品思维 #AI设计 #效率工具`
- **反例**：frontmatter 有 5 个标签，正文末尾只写了 3 个 → 违反规则
