# Skill 分类体系

> 本文件由 SKILL.md 步骤 2 触发加载。用于定位目标 Skill 的类型，决定审查侧重点。

## 5 种分类（来源：skills.sh 生态）

| # | 类型 | 核心特征 | 审查侧重点 |
|---|------|---------|-----------|
| 1 | **Code & Development** | 代码生成/审查/调试/优化，框架最佳实践 | 代码示例准确性、框架版本时效性、最佳实践覆盖度 |
| 2 | **Data & Information Management** | 数据收集/处理/分析/查询/知识管理 | 数据格式规范、查询效率、知识结构清晰度 |
| 3 | **Automation & Orchestration** | 多步骤自动化工作流、多 Agent 协调、工具链集成 | 工作流完整性、步骤间衔接、失败处理、工具依赖声明 |
| 4 | **Specialized Domain & Production** | 特定行业/领域的专家级能力 | 领域知识准确性、边界声明、与通用工具的接口定义 |
| 5 | **Reasoning & Strategic** | 增强推理/规划/战略决策的元技能 | 推理框架清晰度、决策树完整性、边界条件覆盖 |

## 定位方法

1. 读取目标 Skill 的 description + SKILL.md body
2. 判断其主要功能属于哪个类型 → **主类型**
3. 判断是否有明显的次要特征 → **辅类型**（可为空）
4. 一个 Skill 通常是 1 个主类型 + 0-1 个辅类型

## 示例

| Skill | 主类型 | 辅类型 | 理由 |
|-------|--------|--------|------|
| `wechat-short-ppt` | Type 3（自动化） | Type 4（领域专精） | 多步骤工作流 + 公众号竖屏领域 |
| `html-ppt` | Type 3（自动化） | — | 渲染工作流 |
| `wechat-publisher` | Type 2（数据管理） | Type 4（领域专精） | Markdown→微信格式转换 + 微信 API |
| `closed-loop-life` | Type 3（自动化） | Type 4（领域专精） | 多 Agent 协调 + 闭环人生业务领域 |
| `emotion-coach` | Type 5（推理） | Type 4（领域专精） | 情绪分析推理 + 心理学领域 |

## 为什么分类重要

不同类型的 Skill 有不同的质量风险点：
- **Type 3** 最容易漏失败处理和工作流边界
- **Type 4** 最容易领域知识过时
- **Type 5** 最容易决策树不完整
- **Type 1** 最容易代码示例/框架版本过时
- **Type 2** 最容易数据格式不规范

分类后可以针对性加强审查。
